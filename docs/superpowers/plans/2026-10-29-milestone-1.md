# rust_metal Milestone 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Gun Metal runs from the user's files with our recompiled code: front end and the first missions playable with sound effects and music, at the original 30 fps and resolution.

**Architecture:** rustschweine's recompiler core (PE loader, discovery, x86 to Cranelift lifter, JIT, runtime) is copied and pointed at `Gunmetal.exe`, with Ghidra's function list as extra seeds. Win32 imports are implemented in Rust as in rustschweine; D3D9 and DirectSound go to the real system DLLs through guest-side COM wrappers; DirectShow is our own small implementation over Media Foundation (music now, videos skipped until milestone 2).

**Tech Stack:** Rust edition 2024, iced-x86 1.21, cranelift 0.137, winit 0.30 (window only, no GL), `windows` crate (D3D9, DirectSound, Media Foundation bindings), windows-sys 0.61, sha2.

**Spec:** `docs/superpowers/specs/2026-10-29-rust-metal-design.md`

## Global Constraints

- Only `Gunmetal.exe` with SHA-256 `aed26ffbf800da41c741e5d492a01fc1e49da2a54672c70dce48a93fe8cce6e4` is supported; any other: a clear message, exit.
- Never commit anything derived from the EXE except knowledge (addresses, names, descriptions). `game_files/`, `*.iso`, `compiled.bin` stay ignored.
- `cargo test --release` must pass without game files; tests needing them skip with a message when `game_files/Gunmetal.exe` is missing.
- Windows 11 x64 only. No OpenGL. D3D9 and DirectSound are the system's.
- Environment variables use the prefix `GUNMETAL_` (`GUNMETAL_TRACE_API`, `GUNMETAL_SHOT`, `GUNMETAL_INPUT`, ...), same meaning as the `HOGS_` ones in rustschweine.
- Original frame rate and resolution in this milestone; no frame-rate changes to the game's logic.
- Releases must run on other Windows 11 PCs: no overrides tuned to one GPU.
- Code style as in rustschweine: clean Rust, module doc comments that explain the game's behaviour, `data/symbols.txt` updated with every function understood.
- `CLAUDE.md` and `PLAN.md` are kept current at the end of every task that learns something about the game.

## Review Focus

1. Focus loss / Alt-Tab / display mode change (device lost, `Reset`): the game must recover or keep running, not crash. Test in Task 7.
2. D3D9's FPU behaviour: without `D3DCREATE_FPU_PRESERVE`, the real `CreateDevice` sets the caller's x87 to 24-bit precision; our guest x87 is emulated, so the wrapper must set the guest control word the same way, or float results differ from the original. Test in Task 5.
3. Interfaces fetched every frame (`GetBackBuffer`, `GetSurfaceLevel`, `GetRenderTarget`, `GetDepthStencilSurface`) must return the same guest object for the same host object and not grow memory. Test in Task 4.
4. A PC without Media Foundation's WMA decoder (Windows N without Media Feature Pack): one log line, the game runs without music. Test in Task 9.
5. Game folder paths with `!`, spaces or non-ASCII characters (the user's is `C:\!Code2\rust_metal\game_files`) and the game's mixed-case relative paths (`data\frontend\attract_ps.wmv` vs `data/FrontEnd`): files must open. Test in Task 3.

### Task 4: Guest COM wrappers for host interfaces

**Files:**
- Create: `src/platform/com.rs`
- Test: `tests/com.rs`

**Interfaces:**
- Consumes: `platform::com_new(methods: &'static [Import], extra: u32) -> u32`, `alloc`, `free`.
- Produces:
  - `com::wrap(methods: &'static [Import], host: *mut c_void) -> u32`: guest object for a host interface pointer (AddRef'd by the caller's rules); the same host pointer gives the same guest object while it lives.
  - `com::host(this: u32) -> *mut c_void`: the host pointer of a guest object.
  - `com::release(this: u32, host_count: u32)`: when the host's Release returns 0, the guest object and its shadows are freed and the mapping removed.
  - `com::Shadow { guest: u32, size: u32 }` and `com::shadow(this: u32, key: u32, size: u32) -> u32`: a guest buffer per (object, key) kept until release (key: buffer = 0, texture level n = n, cube face/level = face << 8 | level).
  - Guest objects store an index into a host table in their `extra` dword, never a host pointer.

- [ ] **Step 1: Write the failing tests** `tests/com.rs` (host pointers faked with distinct integers, no real COM):
  - `same_host_same_guest`: `wrap(M, p)` twice gives the same address; `host(g) == p`.
  - `no_growth_per_frame`: 10,000 times `wrap(M, p)` then a matching release that leaves the host count > 0: heap top unchanged after the first.
  - `release_frees`: `release(g, 0)` then `wrap(M, p)` gives a new object; its shadow from before is gone.
  - `shadow_stable`: `shadow(g, 0, 4096)` twice gives the same address; size 8192 later gives a buffer of at least 8192.
- [ ] **Step 2:** Run `cargo test --release --test com`. Expected: FAIL.
