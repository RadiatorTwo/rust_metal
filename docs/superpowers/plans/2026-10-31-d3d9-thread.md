# Direct3D 9 on its own thread: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the game's Direct3D 9 work off its main thread. The main thread records the
calls, and a worker thread makes them on the host's device. A picture without a tick drops
from 3.93 ms towards ~3.0 ms on the main thread.

**Architecture:** A new module `src/platform/d3d9/queue.rs` holds a batch of recorded
commands (boxed closures that own copies of every guest pointer's data) and one worker thread
that runs the batches in order. Methods that only set state or draw are recorded and return
`D3D_OK` at once, without handing over the turn. Every other Direct3D method waits until the
worker is idle (`flush`) and then runs as it does today; D3D9 allows that because the device
is created with D3DCREATE_MULTITHREADED. Four parts avoid a flush on the per-picture path:
`Get*State` from a state cache, buffer locks from the kept guest copy, TestCooperativeLevel
from the worker's last answer, and Present recorded with a limit of one picture ahead.

**Tech Stack:** Rust, the `windows` crate (Direct3D 9), `std::sync` (Mutex, Condvar),
`std::thread`.

**Spec:** this plan (the user said "leg los" and skipped the design questions). The
measurements behind it are in PLAN.md "Performance" and in memory `pmc-profile.md`. A
mission picture without a tick takes 3.93 ms: guest code 2.86 ms and imports 1.07 ms, almost
all of it Direct3D (DrawIndexedPrimitive alone is ~3 us a call). The main thread runs at IPC
2.46 and is busy ~93 % of the time.

## Global Constraints

- Only plain D3D9: with `GUNMETAL_D3D9EX=1` (`ex::on()`) the queue is off and everything stays as today.
- Switch: registry value `D3DThread` (key HKLM\SOFTWARE\Rage\Gun Metal, `registry.txt`), default 1; env `GUNMETAL_D3D_THREAD=0` overrides it to off. Off means the calls are exactly as today.
- Never commit anything derived from the EXE; `shot/` and game imagery stay uncommitted.
- `cargo test --release` must pass without game files.
- Benchmarks only per memory `benchmark-method.md`: `.superpowers/bench_game`, delete its `data/SavedGames/[0-9]` before every run, interleaved A/B, 3 rounds each.
- The game's logic must not change: `GUNMETAL_TICK_PRINT` fingerprints of the benchmark script stay identical with the queue on and off (camera, player, game time, objects).
- Recorded commands copy every pointed-to guest datum when they are recorded. The worker never reads guest memory, because the game may change it right after the call returns.
- At most one picture ahead: the main thread's Present waits until the worker has finished the Present before it.

## Review Focus

1. Device loss during a mission (lock screen, UAC, `lose*2000`): the queue must stay usable. The game sees DEVICELOST from TestCooperativeLevel, releases its resources (flushes) and Resets (flush). Expected: same log lines as today, and the front end and the mission draw again. Test: Task 6, step "simulated loss".
2. Release of a texture or buffer that a recorded command still uses: Release flushes first, so the host object outlives its recorded uses. Test: Task 2, `release_waits_for_recorded_use`.
3. Direct3D calls from a guest thread other than the main one (loader 0x4eadf0, if it creates textures): recording is under one mutex, so the order stays the call order. Test: Task 1, `two_threads_record_in_order`.
4. Closing the window or ExitProcess while the worker is busy: ExitProcess and the device's last Release flush first. Expected: no crash and no hang at exit. Test: Task 6 scripted run with `close` at 47 s (mission start, the old R6025 case) and at 100 s.
5. The FPU control word: the worker thread calls D3D9, which may set its own x87 control word; the guest's `Cpu::fcw` is separate and must not change. Expected: tick fingerprints identical (Task 7).

## File Structure

- Create `src/platform/d3d9/queue.rs`: batch, worker thread, `record`, `flush`, `picture_done`, the switch.
- Create `src/platform/d3d9/state.rs`: the state cache (render, texture stage and sampler states).
- Modify `src/platform/d3d9/mod.rs`: `mod queue; mod state;`; CreateDevice starts the worker and fills the cache.
- Modify `src/platform/d3d9/device.rs`: queued variants of the state/draw methods, Present, TestCooperativeLevel, the Get*State methods, Reset.
- Modify `src/platform/d3d9/resources.rs`: buffer Lock/Unlock without a flush, Query Issue queued, Release flushes, state block Apply invalidates the cache.
- Modify `src/platform/mod.rs`: in `on_event`, thunks marked queued skip `turn_give`/`turn_take`; every other `IDirect3D*` thunk calls `queue::flush()` before `f(c)`; ExitProcess flushes.
- Tests: `tests/d3d9_queue.rs`, `tests/d3d9_state.rs`, additions to `tests/d3d9_lock.rs`.
- Docs: CLAUDE.md (Direct3D 9 paragraph, env list), PLAN.md (Performance entry).

### Task 1: The queue and its worker

**Files:**
- Create: `src/platform/d3d9/queue.rs`
- Modify: `src/platform/d3d9/mod.rs` (`pub mod queue;`)
- Test: `tests/d3d9_queue.rs`

**Interfaces:**
- Produces:
  - `pub type Command = Box<dyn FnOnce() + Send>;`
  - `pub struct Queue` with `pub fn new() -> Queue` (starts the worker thread, named `d3d9 worker`), `pub fn record(&self, c: Command)`, `pub fn flush(&self)` (submits the batch and returns when the worker has run everything recorded so far), `pub fn picture_done(&self)` (submits the batch; then blocks until the worker has finished every batch up to the previous `picture_done`), `pub fn pending(&self) -> usize` (commands not yet run, for tests).
  - Global: `pub fn on() -> bool` (switch, see Global Constraints; false when `super::ex::on()`), `pub fn global() -> Option<&'static Queue>` (None when off or before CreateDevice), `pub fn start()` (creates the global queue once; called by CreateDevice).
  - `pub fn flush()` free function: `global().map(Queue::flush)`, a no-op when off.
- Batching: `record` appends to the current batch under a `Mutex`. The batch is handed to the worker when it reaches 256 commands, at `flush` and at `picture_done`, so there is no lock per command on the worker's side. The worker runs batches in order. The worker counts finished commands and pictures, and a `Condvar` wakes `flush` and `picture_done`.

  - `runs_in_record_order`: record 1000 closures that push their index to an `Arc<Mutex<Vec<u32>>>`, `flush()`, assert the vector is `0..1000`.
  - `flush_waits`: record a closure that sleeps 50 ms then sets an `AtomicBool`; after `flush()` the bool is true.
  - `one_picture_ahead`: record a 100 ms sleep, `picture_done()` (returns at once: no previous picture), record a 100 ms sleep, `picture_done()`. That second call returns only after the first sleep has finished (measure ≥ 90 ms from start) and before the second has (< 190 ms).
  - `two_threads_record_in_order`: two threads each record 500 closures that push `(thread, i)`, with a shared mutex taken around each `record` call. After `flush()`, each thread's indices are increasing.

### Task 3: Record the state and draw methods

**Files:**
- Modify: `src/platform/d3d9/device.rs`
- Test: `tests/d3d9_queue.rs`

**Interfaces:**
- Consumes: `queue::global()`, `Queue::record`.
- Produces: a macro `queued!(name, Method, |c| (args...))` beside `pass!`. When `queue::global()` is Some, it evaluates the host arguments at once, records `move || unsafe { (v.Method)(p, args...) }` (with `p` as `usize` so the closure is Send), and returns 0. Otherwise it behaves like `pass!`. Pointer arguments are copied when recorded by these helpers in `device.rs` (pub for tests):
  - `pub fn copy_in(a: u32, n: usize) -> Option<Box<[u8]>>`: None for a = 0; else a copy of guest bytes [a, a+n).
  - Sizes: matrix 64 (SetTransform), D3DVIEWPORT9 24, D3DMATERIAL9 68, D3DLIGHT9 104, clip plane 16, D3DRECT 16 per rect (Clear: `count` rects), shader constants `count * 16` (F, I) and `count * 4` (B).
  - UP draws: the vertex bytes (`primitive_vertices(ty, count) * stride`, or `(min + nv) * stride` with the index bytes for DrawIndexedPrimitiveUP), copied after the existing `up_refused` check. A refused UP draw returns D3DERR_INVALIDCALL without recording.
  - `resources::host_of(...)` is resolved when recorded, never on the worker.
  - The worker logs a failed HRESULT once per method name ("d3d9 worker: SetLight -> 0x...").

### Task 4: The state cache for Get*State

**Files:**

**Interfaces:**
- Produces: `pub struct States { render: [u32; 256], stage: [[u32; 33]; 8], sampler: [[u32; 14]; 16], valid: bool }`, with:

### Task 5: Buffer locks without a flush

**Files:**
- Modify: `src/platform/d3d9/resources.rs` (`buffer_lock`, `buffer_unlock`, a pure helper)
- Test: `tests/d3d9_lock.rs`

**Interfaces:**
- Consumes: `queue::global()`, `Queue::record`, the existing `LOCKS` kept ranges and `com::shadow`.
- Produces:
  - `pub fn lock_needs_host(kept: &[(u64, u64)], lo: u64, hi: u64, flags: u32) -> bool`: false when `flags` has D3DLOCK_DISCARD or D3DLOCK_NOOVERWRITE, or `[lo, hi)` lies inside the kept ranges; true otherwise. READONLY counts as needing the host unless the range is kept.
  - Buffer Lock with the queue on and `!lock_needs_host`: no host call. The buffer's total size comes from a size cached at creation (`created` records it per guest object: add `pub fn buffer_total(this) -> Option<u32>` beside the shadow), so GetDesc is not called. The lock is pushed with `host: 0` and the guest pointer is returned.
  - Buffer Unlock of such a lock (not READONLY): record `move || { host Lock(offset, size, flags); copy bytes; host Unlock }`, with the bytes copied from the shadow at Unlock (`Box<[u8]>`). The lock's flags go along, so DISCARD still renames on the host.
  - When `lock_needs_host` is true: `queue::flush()`, then today's path.

### Task 6: Present, TestCooperativeLevel, queries

**Files:**
- Modify: `src/platform/d3d9/device.rs` (`present`, `test_cooperative_level`, `lost_ended`, `reset`)
- Modify: `src/platform/d3d9/resources.rs` (`query_issue` recorded; `query_get_data` flushes, as every non-queued method)
- Modify: `src/platform/frames.rs` only if its Present columns need the worker's time (see step 3)
- Test: scripted runs (Present needs a device)

**Interfaces:**
- Consumes: `Queue::picture_done`, `Queue::record`.
- Produces:
  - `present` with the queue on records a closure that does everything today's `present` does after `dv(c)`: `shot::before_present`, `letterbox` (its rect computed on the worker), the host Present, `clear_back_buffer`. After the host Present it stores the host's TestCooperativeLevel in `static LAST_COOP: AtomicU32`. Then it calls `picture_done()` and returns 0. The source/dest rects and the dirty region (RGNDATA: header 32 bytes + `nCount * 16`) are copied when recorded.
  - `test_cooperative_level` with the queue on answers `cooperative_level(LAST_COOP, SIMULATED_LOSS, now)` without a host call. `lost_ended` flushes before its own host call.
  - `frames::before_present`/`after_present` stay on the main thread around `picture_done()`: the picture's line then shows when the main thread finished it. The host Present's time goes to a new column `worker_present_ms`, measured in the closure and handed over through an `AtomicU64` that the next picture's line reads.
  - Reset (not queued) flushes; after success it refills the state cache (Task 4) and sets `LAST_COOP` to 0.
